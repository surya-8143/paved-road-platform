# Local Kubernetes runbook

This is a single-node learning environment, tested on Ubuntu 24.04/WSL2 and Docker Desktop. It is not a highly available production cluster. No AWS credentials are used.

## Install and reproduce

Run from a clone of this platform repository using Python 3.12 and the system `python3-yaml` package (tested 6.0.1):

```bash
python3 scripts/install_tools.py kind kubectl helm cosign
export PATH="$HOME/.local/bin:$PATH"
bash scripts/setup_kubernetes.sh
```

Setup uses the separate `~/.kube/paved-road.yaml` file and explicit `kind-paved-road` context. It creates only the `paved-road` kind cluster. The node image, controller images, Argo CD manifest, Helm chart and tools are pinned in the repository. Charts/manifests are checksum-verified before use. Existing named clusters are reused; setup does not delete clusters or touch unrelated Docker containers.

The setup installs Kyverno and Argo CD, applies namespace quotas and admission policies, waits for actual webhook readiness, then enables the demo Application. Argo CD pulls `gitops/` from the public demo repository and reconciles the reviewed image digest. No inbound host ports are exposed by default.

```bash
export KUBECONFIG="$HOME/.kube/paved-road.yaml"
kubectl --context kind-paved-road get applications -n argocd
kubectl --context kind-paved-road get pods -n paved-road-demo
kubectl --context kind-paved-road port-forward -n paved-road-demo service/demo 8080:8080 --address=127.0.0.1
```

Visit `http://127.0.0.1:8080/healthz` or `/docs`. Stop the port forward with Ctrl+C. The counter is process-local memory in this deployment and resets on restart.

## Verify a release and admission

Download the `verified-release` artifact from an approved demo service CI run and the `admission-fixtures` artifact from the demo's manually dispatched fixture workflow. These are public repository artifacts; GitHub authentication may be required to download them. Retention is finite. Do not replace expired evidence with an unverified image or a weaker signer rule.

```bash
python3 scripts/verify_release.py --help
python3 scripts/test_admission.py --release /absolute/path/to/release.json --fixtures /absolute/path/to/admission-fixtures
python3 scripts/test_kubernetes_recovery.py
```

First independently verify the manifest, ZIP and image signatures using the exact repository, source SHA and platform workflow SHA. The admission script consumes that manifest and registry-backed unsigned/wrong-signer fixtures. It uses server-side dry runs and checks denial messages, so an API validation error or a failed download does not count as a policy rejection. The fixture images contain no application and are never deployed.

Policies cover application and init containers, approved GHCR repositories, immutable digests, the exact reusable-workflow signer, signed source-repository/main-branch annotations, resources, read-only filesystems, capabilities and service account tokens. Pod Security Admission enforces Restricted v1.35. Ephemeral containers are explicitly disabled and tested through the actual subresource. Deployment policies are generated by Kyverno; other controllers still create Pods subject to the Pod policies.

## Recovery drills

`test_kubernetes_recovery.py` records raw results in `build/recovery-evidence.json`. It:

1. Rejects a dry-run ephemeral-container update.
2. Changes the demo replica count from one to two and measures Argo CD restoring one, without manual sync.
3. Verifies native admission rejects deleting or scaling the Kyverno controller to zero.
4. Temporarily makes the Kyverno pod unschedulable with desired replicas still one. It checks registered webhooks remain and a trusted Pod is rejected because the webhook cannot be called. A `finally` block restores the exact original template/strategy and waits for recovery.
5. Verifies trusted admission works again and smoke-tests the service over a temporary loopback port forward.

Run this drill only in the disposable project cluster. Interruption of the Python process or WSL itself can prevent `finally` cleanup. In that case, restore the controller from the pinned Helm values with `bash scripts/setup_kubernetes.sh`; do not remove fail-closed webhooks to make a test pass. If a previous Helm process was interrupted, inspect `helm status kyverno -n kyverno` and `helm history` before recovery; never start concurrent upgrades.

`test_recreate_cluster.py --release ... --fixtures ...` requires a clean committed checkout. It verifies the existing container's project label, exact name and pinned image before deleting only the `paved-road` cluster. It recreates everything, confirms the node UID changed, repeats admission/recovery checks, and verifies other Docker containers retain their identity and running state. Output is `build/recreation-evidence.json`.

## The shutdown gap found during testing

Scaling Kyverno to zero initially admitted a valid dry-run Pod: the policy's `failurePolicy: Fail` was insufficient because Kyverno removes managed webhooks during its graceful zero-replica shutdown. This behavior is visible in the pinned [Kyverno server implementation](https://github.com/kyverno/kyverno/blob/v1.20.0/pkg/webhooks/server.go). The chart's `webhooksCleanup.enabled` is a Helm pre-delete hook; turning that setting off alone does not fix controller shutdown cleanup.

`admission-availability.yaml` therefore adds a native API-server ValidatingAdmissionPolicy that rejects zero-replica updates (including `/scale`) and deletion of the admission deployment. It works independently of Kyverno. It prevents operator mistakes; a cluster administrator can still remove this binding, change policies or delete the namespace. Kubernetes admission does not defend against an administrator who can change its controls.

A service-selector-only outage was also insufficient: established API-server keepalive connections could still reach the running webhook. The final drill stops the old controller pod through a temporary Recreate rollout, keeps desired replicas one, and requires the webhook configuration's UID to remain unchanged.

## Limitations and teardown

- One control-plane node and one admission replica are deliberate laptop constraints. Outage rejection reduces availability; it does not keep the application control plane highly available.
- The default kindnet CNI does **not** enforce NetworkPolicy. This project makes no network isolation claim. Upstream manifests containing NetworkPolicy objects do not establish enforcement.
- Registry and Sigstore access are needed for uncached signature checks; their unavailability can reject deployments. Runtime signatures are not a continuous vulnerability scanner.
- Admission prevents new unsafe changes; it does not evict old Pods or replace cluster RBAC. The runtime policy's background scan is disabled because the ephemeral-container subresource is admission-only.
- Argo CD is an administrator-level controller in this local cluster; its AppProject constrains this application to one repository, one namespace, Deployment and Service resources.
- Signed annotations bind the publisher repository/main branch. They are signed by the trusted workflow, not independent certificate claims. The release verifier additionally checks certificate source/workflow identity and manifest hashes.

To remove the disposable project cluster:

```bash
kind delete cluster --name paved-road
```

This removes local cluster state and in-memory counter data. It does not delete Git repositories, GHCR packages, other Docker containers, or AWS resources. To uninstall Kyverno alone intentionally, first remove the `paved-road-admission-availability` binding with the explicit project kubeconfig/context; this is an administrator action that disables that protection.
